# Web_Recon_V3

A full-pipeline website reconnaissance and replication system. Given any public URL, it crawls, analyses, blueprints, and deploys a functional replica through a 12-stage pipeline.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080); served at `/api` and `/recon-api`
- `pnpm --filter @workspace/dashboard run dev` — run the React dashboard (port 23183); served at `/`
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string
- Required secrets: `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`
- Non-secret env vars: `R2_ACCOUNT_ID=69ba6c6060b1f150465b2f7f71fb9b25`, `R2_PUBLIC_BASE_URL=https://pub-8710859f71744960aa5d89e60cf0eb31.r2.dev`

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5 (mounted at `/api` + `/recon-api`)
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod, `drizzle-zod`
- Frontend: React + Vite + Tailwind CSS + Wouter + TanStack Query
- Cloud storage: Cloudflare R2 (with local filesystem fallback)
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (ESM bundle)

## Where things live

- `artifacts/api-server/src/lib/master-orchestrator.ts` — 12-stage pipeline orchestrator (source of truth)
- `artifacts/api-server/src/routes/` — 80+ route files (BM, C, D, E, VR, PH series)
- `artifacts/dashboard/src/pages/` — Dashboard, Jobs, JobMissionControl, RecoveryCenter, DifferentialCenter, ManifestCenter, Storage, Diagnostics, Audit
- `lib/api-spec/openapi.yaml` — OpenAPI source of truth (do NOT change `info.title`)
- `lib/db/src/schema/index.ts` — DB schema source of truth
- `lib/api-client-react/src/generated/` — DO NOT EDIT (regenerated by codegen)
- `lib/api-zod/src/generated/` — DO NOT EDIT (regenerated by codegen)

## Architecture decisions

- API server mounts routes at both `/api` (self-health internal calls) and `/recon-api` (reverse-proxy path); both listed in artifact.toml `paths`.
- `zod` is externalized in `artifacts/api-server/build.mjs` because esbuild can't resolve it through pnpm workspace symlinks when bundling across lib packages; api-server declares `zod` in its own `dependencies` so it is present at runtime.
- Git remote is `github` (not `origin`) — use `git push github main`.
- R2 credentials are Replit secrets; `R2_ACCOUNT_ID` and `R2_PUBLIC_BASE_URL` are plain env vars.

## Product

Web_Recon_V3 is a 12-stage pipeline: crawl → manifest → diff → intelligence → design-dna → visual-dna → stencil → website-prime → merge → deployment-plan → deploy → certification. The React dashboard provides real-time SSE progress, job controls (pause/resume/retry/cancel/clone), recovery engine, differential crawl, manifest center, and R2 storage inspection.

## Gotchas

- Never edit generated files in `lib/api-client-react/src/generated/` or `lib/api-zod/src/generated/`.
- Never change `info.title` in `lib/api-spec/openapi.yaml` — it controls generated filenames.
- Backend imports use `.js` extension in relative imports (TypeScript ESM).
- Never use `console.log` in server code — use `req.log` in route handlers, `logger` singleton elsewhere.
- DB schema changes require `pnpm --filter @workspace/db run push` before first prod deployment.
